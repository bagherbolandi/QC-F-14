## ۱. روش استخراج (به‌محض دریافت فایل)

فایل Excel در واقع یک ZIP است. استخراج بدون تغییر فایل (read-only):

```bash
mkdir -p analysis/raw && cp <file> analysis/src.xlsx
unzip -o analysis/src.xlsx -d analysis/raw > /dev/null
ls -R analysis/raw
```

سپس با اسکریپت پایتون (openpyxl + خوانش مستقیم XML) خروجی‌های زیر گرفته می‌شود:

### الف) ساختار شیت‌ها
- [ ] فهرست نام شیت‌ها + ترتیب + وضعیت visibility (`visible` / `hidden` / `veryHidden`)
- [ ] جهت شیت (`sheetView rightToLeft`) و `RTL` بودن واقعی یا ظاهری
- [ ] `tabColor`، `freezePanes`، `zoomScale`
- [ ] ابعاد UsedRange هر شیت و `dimension` اعلامی
- [ ] شیت‌های دارای `Protection` و رمز (.hasProtection) و نوع اقلام قفل‌شده/باز
- [ ] `dataValidation` در `xl/worksheets/sheetN.xml` → هر قاعده: `type`, `formula1`, `sqref`, `allowBlank`, `showError`, `errorTitle`, `error`, `showInputMessage`, `promptTitle`, `prompt`

### ب) فرمول‌ها و محاسبات
- [ ] فهرست تمام سلول‌های دارای فرمول (آدرس، فرمول انگلیسی + فرمول مادربینی/محلی `xl/sharedFormulas`)
- [ ] شمارش فراوانی توابع: `TODAY` `NOW` `RAND` `OFFSET` `INDIRECT` `CELL` `INFO` (volatileها → ریسک Performance)
- [ ] فرمول‌های ستونی یکسان روی هزاران ردیف (per-row formulas) → نامزد تبدیل به Table/میان‌یاب
- [ ] `COUNTIF/COUNTIFS/SUMIFS` روی محدوده‌های کامل (`A:A`) → ریسک کندى
- [ ] وجود `ARRAYFORMULA` / فرمول‌های پویا (`_xlfn.`) → نشان‌دهنده نگارش در Excel 365
- [ ] `calcChain.xml` و محاسبات دستی (`calcMode`, `fullCalcOnLoad`)

### ج) نام‌های تعریف‌شده (Named Ranges)
- [ ] فهرست `definedName`ها، محدوده، `localSheetId` (شیت‌محور یا کتاب‌محور)
- [ ] `#REF!` یا محدوده‌های شکسته
- [ ] نام‌هایی که به‌عنوان منبع لیست کشویی استفاده می‌شوند

### د) جداول و پیوت‌ها
- [ ] `xl/tables/*.xml` → نام، محدوده، `headerRowCount`، `totalsRowCount`، نام ستون‌ها، `calculatedColumnFormula`
- [ ] `xl/pivotTables/*` + `xl/pivotCache/*` → فیلدها، `cacheSource`، `refreshOnLoad`، `recordCount`، `missingItemsLimit`
- [ ] `xl/connections.xml` → QueryTable / OLAP / لینک خارجی
- [ ] `customXml`, `xl/queries.xml`, `PowerQueryURI` → وجود Power Query
- [ ] `DataModel` / `xl/model/*` → وجود Power Pivot
- [ ] `xl/timelineCaches`, `xl/slicerCaches` → وجود Slicer/Timeline
- [ ] `xl/sortState`, AutoFilter هر شیت

### هـ) فرمت سلول‌ها (بسیار مهم برای تاریخ و بارکد)
- [ ] `numFmt`های سفارشی مربوط به تاریخ → تشخیص الگوی شمسی (`yyyy/m/d` در برابر `[$-fa-IR,1304]m/d/yyyy` در برابر رشته متنی)
- [ ] `numFmt` بارکد: `@` (Text) یا `General`/`0` (عدد) → اگر عدد باشد، **از دست رفتن ارقام ۱۶ تا ۱۹ قطعی است**
- [ ] ستون‌های `t="s"` (رشته) در برابر `t="n"` (عدد) برای بارکد
- [ ] الگوی `Merge Cells` (تعداد و موقعیت) → مانع ساخت Table و فیلتر
- [ ] `conditionalFormatting`ها (قاعده + محدوده) → ریسک Performance و «رنگ تزئینی بدون معنا»
- [ ] تعاریف `styles.xml` (تعداد سبک‌ها — تورم سبک = فایل سنگین)

### و) فیلدها و معنا (Data Dictionary معکوس)
برای هر شیت/جدول: [نام ستون] | [نوع داده واقعی در سلول] | [nullable] | [حالت ورود: دستی/فرمول/لیست] | [منبع لیست] | [کلید اصلی؟] | [وابستگی به فیلد دیگر]

### ز) کیفیت داده (روی داده واقعی، نه ساختار)
- [ ] تعداد رکورد، بازه تاریخ، توزیع رکورد بر حسب روز/شیفت
- [ ] بارکد: طول‌های مشاهده‌شده، صفر ابتدایی، کاراکتر غیررقمی، رشته‌های `########` یا `1.23E+18`، تکراری
- [ ] تکرار رکورد (کلید تکرار پیشنهادی: تاریخ+شیفت+ایستگاه+بازرس+بارکد)
- [ ] یتیم (orphan): مقدار موجود در رکورد که در لیست اطلاعات پایه نیست (با تغییر نام، حذف، یا حذف ردیف لیست)
- [ ] رکورد ناقص (هر فیلد الزامی خالی)
- [ ] تاریخ آینده / تاریخ قبل از شروع خط / شیفت‌های متنی ناهمسان («۱»، «1»، «شیفت اول»)

### ح) ریسک‌های بسته‌بندی فایل
- [ ] نوع فایل (`xlsx` بدون ماکرو در برابر `xlsm`) — اگر ماکرو دارد: استخراج `vbaProject.bin` + دی‌کامپایل برای خواندن منطق (فقط خواندنی)
- [ ] وجود `xl/ctrlProps/*` (کنترل‌های ActiveX / فرم) → وابستگی به VBA
- [ ] `VBA project` محافظت‌شده با رمز؟ (در این صورت فقط رفتاری تحلیل می‌شود، نه کد)
- [ ] `externalLinks` → لینک به فایل دیگر روی شبکه (شکننده‌ترین وابستگی ممکن)
- [ ] حجم فایل و نسبت حجم به تعداد رکورد

## ۲. چک‌لیست سؤال‌هایی که فایل نمی‌تواند جواب دهد

این‌ها حین بازبینی فایل مشخص **نمی‌شوند** و باید از صاحب فرآیند پرسیده شوند:

1. نسخه دقیق Excel و محیط اجرا (Desktop 365 / 2019 / 2016، ۳۲ یا ۶۴ بیت، مجوز ماکرو توسط IT).
2. آیا فایل روی شبکه با اشتراک همزمان استفاده می‌شود؟ چند نفر همزمان در یک شیفت؟
3. آیا Power Pivot / Power Query روی سیستم‌های خط مجاز و در دسترس است؟
4. قاعده واقعی شماره بارکد: همیشه ۱۹ رقم؟ صفر ابتدایی؟ حرف‌دار؟ الگوریتم کنترلی (checksum) دارد؟
5. تعریف کسب‌وکاری دقیق «برگشتی / ضایعات / اصلاحی» — آیا از یک فیلد «وضعیت قطعه» مشتق می‌شود یا نوع رخداد جداست؟
6. رابطه قطعه↔قالب و قطعه↔عیوب: آیا در سازمان واقعاً تعریف‌شده است یا هر بازرس مختار است؟
7. مبنای محاسبه نرخ ضایعات: مخرج کسر کجاست (تعداد تولید شده از کجا می‌آید)؟ در فایل فعلی اصلاً داده تولید وجود دارد؟
8. خط مشی نگهداشت داده: چند سال؟ آرشیو سالیانه؟
9. آیا نیاز به امضا/تأیید سرشیفت روی رکورد ثبت‌شده هست؟

## ۳. قالب گزارش خروجی فاز ۱ (پس از دریافت فایل)

بخش‌های A تا J مطابق درخواست، با این قاعده که **هر ادعا باید به شواهد فایل ارجاع دهد** (نام شیت، آدرس سلول، نام قاعده اعتبارسنجی، شماره ردیف XML). هیچ ایرادی که در فایل دیده نشده، در گزارش نمی‌آید؛ هیچ رابطه‌ای که در داده یا منطق کسب‌وکار قابل دفاع نباشد، پیاده‌سازی نمی‌شود.
