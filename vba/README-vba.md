# لایۀ ماکرو — `QC_WritePath.bas`

فایل تحویلی (`QC-F-14-v2.xlsx`) عمداً **بدونِ ماکرو** ساخته شده است. این ماژول تنها قطعهٔ
VBA کل سامانه است و فقط «مسیرِ نوشتن» را انجام می‌دهد؛ هر محاسبه‌ای (گزارش‌ها، داشبورد،
DQ، Pareto، سهم‌ها) فرمولِ داخلِ شیت است. قانونِ «فرمول محاسبه می‌کند، VBA می‌نویسد» که در
فاز ۱ تأیید شد، همین‌جا اجرا شده است.

## نصب (یک‌بار، ~۲ دقیقه)

1. `QC-F-14-v2.xlsx` را باز کنید و **Save As → Excel Macro-Enabled Workbook (*.xlsm)** بزنید
   (یا همان فایل را کپی کنید و روی کپی کار کنید).
2. `Alt+F11` → منوی **File → Import File…** → `vba/QC_WritePath.bas`.
   ماژول با نام `QC_WritePath` اضافه می‌شود.
3. در Excel: **File → Options → Trust Center → Trusted Locations** → پوشۀ فایل را اضافه کنید
   (یا هنگام باز کردن، Enable Content). با این کار هشدارِ ماکرو هر بار تکرار نمی‌شود.
4. دکمه‌ها: در شیت «FORM فرم ثبت» از تب **Developer → Insert → Rectangle** یک شکل بکشید،
   راست‌کلیک → **Assign Macro**:

   | برچسبِ پیشنهادی | ماکرو | کاری که می‌کند |
   |---|---|---|
   | ثبت | `QC_Append` | ۹ فیلد فرم را می‌خواند، اعتبارسنجیِ نهایی را اجرا می‌کند، **یک** سطر به `tblQC` اضافه می‌کند، یک سطر به `LOG_AUDIT` و بارکد را برای اسکنِ بعدی پاک می‌کند |
   | ورودِ STAGING | `QC_Import_Staging` | ردیف‌های STAGING که ستون FLAG آن‌ها «✓ آماده Import» است را به `tblQC` می‌فرستد و همان ردیف‌هایِ STAGING را پاک می‌کند (قراردادِ خودِ شیت) |
   | ابطالِ ردیف | `QC_VoidRow` | روی یک سلول از ردیفِ Data کلیک کنید؛ فقط `ROW_STATUS` را «ابطال‌شده» می‌کند — **حذف نمی‌کند** |
   | پاک‌کردن فرم | `QC_ClearForm` | فقط ۹ سلولِ ورودی (برچسب‌ها دست نمی‌خورند) |
   | درباره | `QC_About` | نسخه، شمارۀ رکوردها، کاربر و نامِ رایانه — و مرزهایِ صریح |

5. اگر خواستید میان‌بر بگذارید: **View → Macros → `QC_Append` → Options** (مثلاً `Ctrl+Q`).

## کد چرا فارسی ندارد (و چرا این یک باگ نیست)

VBE یک ویرایشگرِ ANSI است. فارسیِ تایپ‌شده درونِ فایل `.bas` هنگامِ Import از کدصفحۀ
ویندوز عبور می‌کند؛ در `cp1256` نه ZWNJ (U+200C) هست و نه `ی` فارسی (U+06CC) — یعنی
«تأییدشده» و «هم‌خوان» درستِ خودشان قابلِ ذخیره نیستند. پس در این ماژول **هیچ literalِ
فارسی وجود ندارد** و همهٔ رشته‌ها از خودِ فایل خوانده می‌شوند:

| چه چیزی | از کجا |
|---|---|
| وضعیت‌هایِ رکورد (`تأییدشده`/`ابطال‌شده`/`مشکوک-تکراری`) | `Helper محاسبات!CODE_ROW_STATUS` (با اندیس) |
| مقدارهایِ `MOLD_CHECK` (`هم‌خوان`/`ناهم‌خوان`/…) | `Helper محاسبات!CODE_MOLD_CHECK` |
| نوعِ رخداد | `Master!DIM_DISPOSITION[نوعِ رخدادِ قطعی]` و سپس `Master!RULE_STATION` |
| نامِ شیت‌ها | `Settings!QC_SHEETS` (تغییرِ نامِ شیت = ویرایشِ همین ۸ سطر) |
| متنِ پیام‌ها و برچسبِ کانالِ ثبت | `Settings!QC_MSG` (۱۷ کلید، قابلِ ویرایش) |
| تقویمِ جلالی | جست‌وجو در گریدِ تقویمِ Helper (`QC_CAL_G`, `QC_CAL_MK`, `QC_CAL_WK`) |

نتیجه: الگوریتمِ تقویم در VBA **تکرار نشده**، هیچ وابستگی به locale ویندوز نیست، و اگر
رشته‌ای را در فایل عوض کنید، ماکرو هم همان را می‌نویسد.

## قرادادهایِ ریز اما سرنوشت‌ساز

- **بارکد**: فقط به‌صورتِ متن و دقیقاً ۱۹ رقم (`RawText` و `.Text` می‌خواند تا اگر صفرهایِ
  ابتدا خورده شده باشند، رکورد **ثبت نشود** و پیامِ فارسیِ `E_BARCODE` را ببینید). ستونِ
  مقصد قبل از نوشتن `@` (Text) می‌شود.
- **بارکدِ تکراری**: رد نمی‌کند. ردیف را با `ROW_STATUS = مشکوک-تکراری` می‌نویسد و پیامِ
  «ثبت شد + علامت‌گذاری شد» را نشان می‌دهد. تاریخچه حذف نمی‌شود.
- **ظرفیت**: اگر ردیفِ خالیِ `tblQC` نماند، ثبت را **متوقف** می‌کند (نه اتساعِ خودِ Table).
  راهنمایِ بایگانی/مهاجرت سالانه: شیت Help، بند ۸.
- **قاعدهٔ ایستگاهِ بی‌قاعده**: اگر ایستگاهی در `RULE_STATION` ردیفِ قاعده نداشته باشد،
  ماکرو با پیامِ `E_NORULE` می‌ایستد — نوعِ رخداد را حدس نمی‌زند.
- **LOG_AUDIT**: best-effort است. اگر ۲۰۰ سطرِ آن پر شود، ماکرو فقط ثبتِ لاگ را رد می‌کند و
  داده را نه. این شیت «اثرِ انگشت» است، نه ممیزیِ قانونی (بند G گزارش فاز ۱).
- هرگز `Unprotect`، `SaveAs`، `Shell`، حذفِ ردیف، یا نوشتنِ فرمول انجام نمی‌دهد؛
  `tools/make_vba.py` همین ممنوعیت‌ها را به‌عنوانِ آزمون اجرا می‌کند.

## راستی‌آزمایی (بدونِ Excel)

```bash
python3 -W ignore tools/make_vba.py vba/QC_WritePath.bas --workbook QC-F-14-v2.xlsx
```

۲۳ بررسی: ASCII/CRLF بودن منبع، تعادلِ بلوک‌ها، نبودِ کدِ مرده، لیستِ ممنوعه‌هایِ رفتاری،
و مهم‌تر از همه **قراردادِ ماژول↔فایل**: هر توکنِ ستون، هر نامِ جدول، هر نامِ
تعریف‌شده، هر کلیدِ `QC_MSG`/`QC_SHEETS`، و هر اندیسِ گرید باید در فایلِ ساخته‌شده وجود
داشته باشد. اگر ترتیبِ `CODE_ROW_STATUS` یا `CODE_MOLD_CHECK` عوض شود، این آزمون قرمز
می‌شود (نه Excelِ کاربر). `T-V3 WriteRow هر ستونِ tblQC را پر می‌کند` هم همان بیماریِ
فایلِ قبلی («نیمه‌پرشدنِ سطر») را هدف می‌گیرد: هر ۲۶ ستون باید نوشته شود.

## آنچه تأیید **نشده**

این ماژول در Excel اجرا نشده (محیطِ ساختِ ما Excel ندارد). منطقِ خالصِ آن (تقسیمِ
«کد | نام»، جست‌وجو در تقویم، قاعدهٔ EVENT_TYPE، MOLD_CHECK، ردیفِ بعدی، منطقِ حلقۀ لاگ)
در Python روی همان payload پیاده و تست شده است، ولی **سمتِ VBA/COM** — Assign Macro،
رفتارِ `Application.Match` روی نام‌ها، رفتارِ COUNTIF روی رشته‌هایِ ۱۹ رقمی — باید در
ایستگاهِ اول دستی آزموده شود. چک‌لیستِ ۱۰‌بندیِ پذیرشِ دستی در `analysis/04-build-and-handoff.md` §۵ برای همین نوشته شده است.

اگر سیاستِ IT ماکرو را بلاک کرد: هیچ‌چیز نمی‌شکند — شیت `STAGING ورود اضطراری` راهِ
بدونِ ماکرو است و فرمول‌هایش همان اعتبارسنجی‌ها را نشان می‌دهد.
